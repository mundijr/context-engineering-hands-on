Agentic Document Retrieval

The core teaching module. Agent.messages is the context window — every user message, tool call, and tool result is a visible entry in one growing Python list, re-sent on every API call.

Selecting Context agent.py retrieval.py tools.py app.py

Architecture

Sequence — one turn, start to finish

What this teaches

  • The system prompt costs roughly 200 tokens on every call — a fixed tax paid for the whole conversation. agent.py:25
  • self.messages grows monotonically; nothing leaves the window unless /clear resets it. agent.py:83–92
  • A single get_document call can inject 500+ tokens into the window — permanently, until cleared. agent.py:158–161
  • Tool schemas (~800 tokens) are sent on every call whether or not the model ends up using them. tools.py:5–9
demos/chat-with-artifacts/

Chat with Artifacts

A FastAPI chat app where every reply can carry one structured artifact — a quiz, a flowchart, a flashcard deck. The system prompt is assembled fresh each turn from three layers with three different price tags.

Writing Context app.py schemas.py static/index.html

Architecture

Sequence — one message, one artifact

What this teaches

  • Three layers, three lifecycles: fixed persona (~150 tok), static artifact catalog (~400 tok), and a dynamic summary that only grows once artifacts exist. app.py:42–53
  • One flat tool schema merges all 8 artifact types; the artifact_type enum is the discriminator, since the API forbids top-level anyOf/oneOf. schemas.py:374–386
  • The model's own tool_use block is stored back into history verbatim — strip it and the model "forgets" what it already created. app.py:202–209

Chat Agent Overview

Three independent scripts, each one rung more capable than the last — from a single structured-output call, to a browser quiz, to a full tool-calling loop that mixes a server-side tool with local ones.

Structured Output structured_output_example.py quiz_app.py chat.py

Architecture — three rungs

Sequence — chat.py's tool loop

What this teaches

  • structured_output_example.py is the smallest possible messages.parse call — one prompt, one Pydantic schema, one parsed object, no server.
  • quiz_app.py extends that schema with correct_index so grading happens entirely client-side, with zero extra API calls.
  • chat.py mixes a server-side tool (web_search) with local ones — the same tools array, two very different execution paths. chat.py:108–112
demos/full_agent_app.py

Agentic-RAG CLI

The same document-retrieval idea as demo 01, rebuilt on claude_agent_sdk. The tool loop, and the context window it runs on, now live inside ClaudeSDKClient — your code never sees a messages list.

Delegating the Loop full_agent_app.py claude_agent_sdk

Architecture

Sequence — one question, SDK-managed

What this teaches

  • ClaudeSDKClient owns the context window internally — there's no messages list in this file to inspect, unlike agentic-retrieval/agent.py.
  • Tools are plain async functions decorated with @tool, served over an in-process MCP server instead of hand-written JSON schemas. full_agent_app.py:48–104
  • max_turns=10 on ClaudeAgentOptions is the SDK's version of agent.py's MAX_TOOL_ROUNDS safety limit. full_agent_app.py:138
